# ESP32-P4 第一阶段最小移植与接线方案

> 适用目标板：慧勤智远 ESP32-P4 CB V1.2  
> 适用屏幕：TS040HDS02CP-B1620A（TR230S，720 × 720）  
> 文档状态：接线与软件方案已审计；尚未完成本次 P4 真机烧录和硬件验证。  
> 安全原则：照片、Pin 1、供电和通断测试未确认前，不给屏幕上电。
> 2026-07-11 更新：屏幕已改为 20-pin FPC 转杜邦的 SPI-4WIRE + FT6336U 方案，逐脚接线只以 [P4_TR230S_SPI4WIRE_FT6336U接线方案.md](P4_TR230S_SPI4WIRE_FT6336U接线方案.md) 为准；旧 QSPI/2×7 接法已停用。

## 1. 第一阶段范围

### 1.1 本阶段目标

本阶段只建立最小、可独立验收的 P4 硬件基础链路：

1. **Wi-Fi**：ESP32-P4 通过板载 ESP32-C6，使用 SDIO + `esp_hosted` + `esp_wifi_remote` 联网。
2. **麦克风**：使用板载驻极体麦克风和 ES8311，仅验证 16 kHz / 16-bit / 单声道录音；`PA_CTRL`（GPIO11）保持低电平，不播放扬声器。
3. **屏幕与触摸**：TR230S 使用 SPI-4WIRE，FT6336U 使用独立 I²C；均由 20-pin FPC 转杜邦板接开发板 GPIO 排针，先以 10 MHz 显示静态色块并输出触摸坐标。
4. **TF 卡**：验证板载卡座的识别、挂载和读写自检。64 GB 卡若不是当前固件可挂载的 FAT32，只在用户明确确认数据可清空后格式化。
5. **串口控制**：使用板载 CH343P 对应的 UART0，115200 波特率，完成烧录、日志监视和 JSON Lines 测试。

### 1.2 本阶段非目标

- 不接入 OV5647 摄像头，也不验证摄像头与 ES8311 共享 GPIO28/29 I2C 的并发业务。
- 不恢复完整 LVGL 页面、动画和业务 UI；屏幕先显示静态测试图案。
- 不再使用屏幕原生 2.00 mm 2×7 接口；本阶段固定使用逐脚独立引出的 20-pin FPC 转杜邦板。
- 不验证扬声器、NS4150B 功放、语音唤醒、ASR、AI、摄像头、OTA 和完整业务组件。
- 不把“编译通过”写成“硬件通过”；每项真机结论必须有串口日志和实物现象支撑。

## 2. 开发板端识别方式

本方案不使用原理图里的 `P6` 编号。开发板端只按实板 GPIO 丝印接线：例如表格中的 `07` 就接标有 `07` 的针脚，`5V`、`3V3`、`GND` 也直接按丝印识别。若实物没有这些丝印或看不清，先拍开发板正面排针高清照片确认，不要靠物理脚序猜测。

屏幕端仍必须找到 FPC 转接板明确的 Pin 1 标记，并用万用表通断档逐脚确认。

## 3. 当前屏幕方案：20-pin FPC 转杜邦

转接板必须把屏幕 FPC **逐脚独立引出**，并能明确确认 FPC Pin 1 方向。开发板端按实板 `07`、`08` 等 GPIO 丝印接线，不再使用原理图连接器代号数脚。

> **严禁把 TR230S 的 20-pin FPC 直接插进开发板板载 20-pin SPI 屏座。**  
> 开发板屏座 Pin1/2 是 5V、Pin3/4 是 GND；TR230S FPC Pin1 是 GND、Pin2 才是 5V。直插会把 5V 加到屏幕 GND 网络，存在立即烧毁屏幕或开发板的风险。板载 20-pin SPI 屏座在本方案中保持空置。

### 3.1 20-pin FPC 显示部分

| FPC Pin | 信号 | 开发板丝印 | P4 信号 | 处理 |
| ---: | --- | ---: | --- | --- |
| 1 | GND | `GND` | GND | 公共地 |
| 2 | VCC | `5V` | 5V | 屏幕主电源 |
| 3 | GND | `GND` | GND | 公共地 |
| 4 | CS# | `07` | GPIO7 | SPI 片选 |
| 5 | GND | `GND` | GND | 公共地 |
| 6 | SDO1 / MISO | `10` | GPIO10 | SPI MISO |
| 7 | SDO0 / MOSI | `08` | GPIO8 | SPI MOSI |
| 8 | SCL / SCLK | `09` | GPIO9 | SPI Mode 0，10 MHz 起步 |
| 9 | SDO3 | 不接 | — | 仅 QSPI 使用 |
| 10 | SDO2 | 不接 | — | 仅 QSPI 使用 |
| 11 | RESET# | `22` | GPIO22 | 低有效复位 |
| 12 | WAIT# | `19` | GPIO19 | 忙状态输入 |
| 13 | QSPI-INT | 不接 | — | 主控直接访问 FT6336U 时不需要 |
| 14 | D/C# | `20` | GPIO20 | 低=命令，高=数据/参数 |

### 3.2 FT6336U 直接 I2C 触摸部分

| FPC Pin | 触摸信号 | 开发板丝印 | P4 信号 | 处理 |
| ---: | --- | ---: | --- | --- |
| 15 | TP-INT | `15` | GPIO15 | 触摸中断 |
| 16 | TP-SDA | `17` | GPIO17 | 独立 I2C SDA，100 kHz 起步 |
| 17 | TP-SCL | `16` | GPIO16 | 独立 I2C SCL，100 kHz 起步 |
| 18 | TP-RST | `18` | GPIO18 | 触摸复位，低有效 |
| 19 | TP-VCC | **不接** | — | 规格标注 `NC (Shared screen power supply)`；除非供应商和转接板原理图明确证明需要外供，否则保持悬空，禁止自行接 5V，也不默认接 3.3V |
| 20 | TP-GND | `GND` | GND | 接公共地 |

`TP-SDA` 与 `TP-SCL` 各需要约 4.7kΩ 上拉到 3.3V；转接板已有 3.3V 上拉时不要重复并联。FT6336U 固件地址为旧 S3 实物已验证的 `0x48`。

## 5. 上电前硬件安全检查表

### 5.1 断电状态

- [ ] 开发板 USB、电源和屏幕全部断开，至少等待 10 秒后再插拔排线。
- [ ] 已拍到开发板 P6 正面、P6 Pin 1、屏幕接口正反面和屏幕 Pin 1；照片足以看清丝印。
- [ ] 已确认使用 20-pin 独立 FPC 转杜邦板，没有混用屏幕原生 2×7 或开发板板载 20-pin 屏座的脚序。
- [ ] 板载 20-pin SPI 屏座为空，TR230S FPC 没有直插该座。
- [ ] 屏幕 VCC 只接 5V；所有 GPIO 逻辑均为 3.3V，不存在 5V 信号回灌。
- [ ] 屏幕、开发板和转接板共地；三个显示 GND 均进入同一公共地网络。
- [ ] 用万用表通断档逐线核对：屏幕 Pin → 转接点 → P6 物理脚，结果与表格一致。
- [ ] 检查相邻针无锡桥/短路；VCC 与 GND 不持续蜂鸣。电容充电造成的瞬时蜂鸣不能代替阻值判断。
- [ ] CS、MOSI、MISO、SCLK、D/C、RST、WAIT 均没有与 5V 或 GND 短接。
- [ ] 接线尽量不超过 10 cm；SCLK、MOSI、D/C、CS 贴近地回路，避免绕过 Wi-Fi 天线区域。
- [ ] TF 卡在断电时插好；后续测试期间不热插拔。

### 5.2 首次带电测量

1. **先不接屏幕**给开发板供电，确认丝印 `5V` 对 `GND` 约为 5V，丝印 `3V3` 对 `GND` 约为 3.3V。任何测量明显异常都先断电排查。
2. 断电后再接屏幕。不要同时用两个不同的 5V 电源给 USB 和 P6 反向供电，除非已确认防反灌路径。
3. 使用稳定 5V/2A 电源。板上保险丝额定约 1.5A，屏幕背光、C6 Wi-Fi 和其他外设同时工作时仍需关注总电流与压降。
4. 首次 SPI-4WIRE 固定 10 MHz，不直接使用旧 S3 QSPI 真机曾达到的 40 MHz。短线和 10 MHz 稳定后再单独评估提速。
5. 上电后手指不直接触碰裸露 FPC/排针；出现异味、异常发热、冒烟、电压塌陷或反复复位时立即断电。

## 6. 分阶段验证步骤与成功判据

必须按顺序进行。前一阶段不通过时，不同时加入更多外设，以免把问题混在一起。

### 6.1 阶段 0：软件构建

在项目根目录运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\idf.ps1 build
```

当前软件状态：工程目标已切到 `esp32p4`，ESP-IDF 6.0.1 配置生成已成功；完成 OTA 健康确认和 SDMMC 共享控制器修复后，从空 `build/` 目录执行的干净全量构建已生成 `build/fridge_spirit.bin`，二进制为 `0xcb4b0` 字节（832,688 字节），SHA-256 为 `C9A8B0D1F53BBFEB85758637CF653498793001B592F0400A2B479150CE310186`，最小 2 MiB App 分区约剩余 60%。构建日志中的配置、C/C++ `warning:`/`error:` 均为 0。这只证明编译和链接通过，**不代表 P4、C6、麦克风、屏幕或 TF 卡已在真机通过**。任何后续源码或 `sdkconfig` 变更后都要重新执行完整构建。

成功判据：命令退出码为 0，输出包含 `Project build complete` 或镜像成功生成信息，分区检查无溢出。

### 6.2 阶段 1：裸板、串口与基础启动

1. 屏幕暂不连接，先连接开发板标注为 COM/UART 的 USB-C 口。
2. 在设备管理器或 PowerShell 查找新增的 CH343P 串口：

```powershell
Get-CimInstance Win32_SerialPort | Select-Object DeviceID, Name
```

3. 把实际端口代入以下命令；旧 S3 的 `COM16` 不得沿用：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\idf.ps1 -p COMx flash monitor
```

4. 在 115200 波特率日志中观察完整启动过程。串口协议会先发送 `booting` 事件；此时除静态 `get_pins/get_logs` 外的命令都会返回“等待 ready”，用于避免上位机和硬件初始化并发。屏幕未接时允许出现“屏幕未就绪”类错误，但不能导致崩溃或反复复位。
5. 等收到 `ready` 事件后，再向串口发送一行 JSON，并以换行结束：

```json
{"request_id":"status-1","command":"get_status"}
```

成功判据：芯片识别为 ESP32-P4；Flash/PSRAM 初始化正常；先后收到 `booting`、`ready`，随后收到匹配 `request_id` 的 JSON 响应；日志没有 brownout、PSRAM 初始化失败、Guru Meditation、watchdog 循环或 heap overflow。

### 6.3 阶段 2：C6 SDIO 与 Wi-Fi

本阶段无需外接线。P4 与板载 C6 使用 SDIO；软件分配为 hosted 使用 SDMMC Slot 1，TF 卡使用 Slot 0。两个槽共享 P4 的同一个 SDMMC 控制器：TF 挂载必须复用 hosted 已初始化的 host，只新增和释放 Slot 0，不能二次初始化或整体反初始化控制器。C6 hosted 链路持有板载可调 LDO4，不能让 TF 组件重复申请同一 LDO。

1. 先在启动日志中确认 SDIO 枚举和 P4/C6 hosted 握手成功，没有持续 timeout、CRC 或 slave firmware 不匹配错误。
2. 扫描周围 2.4 GHz Wi-Fi：

```json
{"request_id":"wifi-scan-1","command":"scan_wifi"}
```

3. 再设置测试网络；密码只发送，不应出现在响应和普通日志中：

```json
{"request_id":"wifi-set-1","command":"set_network","ssid":"你的2.4G_SSID","wifiPassword":"你的密码","save":true}
```

4. 查询状态：

```json
{"request_id":"wifi-status-1","command":"get_network"}
```

成功判据：扫描返回真实 AP；连接后 `connected:true` 并获得合理 IP；密码未被回显；连续运行 10 分钟无 SDIO 重连风暴、brownout 或系统复位。若 hosted 初始化失败，本次启动会锁定首次错误并跳过 TF，必须修正原因后重启，禁止在半初始化状态下反复扫描。若 hosted 报版本不匹配，先核对/更新 C6 slave 固件，不能先归咎于业务代码。

### 6.4 阶段 3：板载 ES8311 麦克风

1. 确认没有接扬声器，且日志表明 `PA_CTRL=GPIO11` 保持低电平。
2. 开始录音，对板载麦克风正常说话 3～5 秒：

```json
{"request_id":"mic-start-1","command":"mic_record_start"}
```

3. 查询录音状态：

```json
{"request_id":"mic-status-1","command":"mic_record_status"}
```

4. 停止录音并获取 WAV：

```json
{"request_id":"mic-stop-1","command":"mic_record_stop"}
{"request_id":"mic-wav-1","command":"mic_record_wav"}
```

成功判据：ES8311/I2S 初始化无错误；`pcmBytes`、`sampleCount`、`rms`、`peakAbs` 随说话产生非零数据；`timeoutCount` 不持续增长，`clipCount` 不大量增加；WAV 标明 16000 Hz、单声道、16-bit，解码后能听清测试语音。若数据全零、满幅或只有固定噪声，不算通过。

### 6.5 阶段 4：TR230S SPI-4WIRE 屏幕与 FT6336U

1. 再次断电，按第 3 节或第 4 节连接屏幕；完成通断与电压复核后才上电。
2. 保持 SPI-4WIRE 10 MHz，先运行静态色块测试，不启用完整 LVGL。
3. 观察屏幕和串口至少 10 分钟。若出现白屏，不能仅凭背光点亮判成功；白屏通常只证明供电/背光存在。

成功判据：日志显示 TR230S 初始化完成且 WAIT# 没有持续超时；屏幕能稳定、完整地显示白、红、绿、蓝、黑等预期色块，无花屏、错色、撕裂、随机闪烁；Wi-Fi 同时工作时不复位、不明显发热。只有 10 MHz 稳定后才可按 10 → 20 MHz 单步提速，每次重新做稳定性观察。

如果使用 20-pin FPC 转接板并单独启用触摸，附加成功判据是 I2C 发现预期 `0x48` 且坐标随触点移动；触摸失败不能推翻已经独立通过的显示结论。

### 6.6 阶段 5：64 GB TF 卡

Wi-Fi hosted 初始化完成后再验证 TF 卡，避免混淆两个 SDMMC 槽和 LDO4 的问题。

1. 先查询，不自动格式化：

```json
{"request_id":"tf-status-1","command":"get_tfcard_status"}
```

2. 如果 `mounted:true`，直接执行读写自检：

```json
{"request_id":"tf-test-1","command":"tfcard_selftest"}
```

3. 只有返回 `formatRequired:true`，并且再次确认 64 GB 卡内数据可全部清空时，才发送精确确认口令：

```json
{"request_id":"tf-format-1","command":"format_tfcard","confirm":"ERASE_TF_CARD"}
```

该操作不可恢复，64 GB 卡格式化可能持续数十秒。不得掉电、复位或拔卡。格式化完成后重新执行状态查询和自检。

成功判据：`mounted:true`，容量与 64 GB 卡的实际可用容量大致匹配；自检完成固定测试文件 `/sdcard/fridge_selftest.txt` 的覆盖写入和读回校验；复位后仍可重新挂载。任何格式化动作及结果都必须记录，不能只根据“TF 已插入”写成通过。

## 7. 当前待确认项

以下信息必须由实物或真机日志补齐：

1. **屏幕接口照片**：确认 20-pin FPC 独立转接板、屏幕 Pin 1 和 SPI 硬件模式清晰可辨。
2. **GPIO 丝印照片**：需提供开发板正面全景和底部 GPIO 排针近照，确认 `5V/3V3/GND/07...22` 等丝印。
3. **实际 COM 号**：当前尚未识别到 P4 板 CH343P 的新增 COM 口；旧 `COM16` 是 S3 记录，禁止复用。
4. **C6 slave 固件匹配**：板载 C6 当前固件版本及其与本工程 `esp_hosted 2.2.3` / `esp_wifi_remote 0.15.0` 的握手结果待真机日志确认。
5. **TF 卡真机状态**：64 GB 卡的当前文件系统、容量、能否挂载、是否需要 FAT32 格式化及自检结果均未确认；目前没有执行格式化。
6. **整机供电余量**：5V 电压、C6 联网和屏幕背光同时开启时的压降、温升与稳定性待测。

在以上照片和端口信息未补齐前，可以继续做软件构建和静态检查，但不执行屏幕上电、烧录后外设联调或 TF 格式化。

## 8. 记录要求

每次真机测试至少记录：日期、固件 commit/二进制、实际 COM 口、供电方式、屏幕连接方案、逐脚接线照片、SPI 时钟、TF 卡状态和完整启动日志。只有满足对应成功判据的项目才能在 `doc/progress.md` 和 `doc/memory.md` 中标记为“P4 真机已验证”。
