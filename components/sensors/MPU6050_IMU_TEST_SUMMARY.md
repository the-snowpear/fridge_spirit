# ESP32-P4 MPU6050 接入说明

> 当前状态：P4 驱动、启动编排、USB `get_sensors`、本机 UI 和 WebUI 已完成代码接入；仍需在真实扩展板上构建、烧录并完成接线/上拉/长稳验证。旧 ESP32-S3 实测记录保留在 `s3-legacy` 分支与 `s3-final-20260702` 标签，不再作为主线接线依据。

## 当前硬件基线

| 信号 | ESP32-P4 | 模块要求 |
| --- | --- | --- |
| VCC | 扩展板 3.3V | 禁止接 5V |
| GND | 共地 | 必须可靠共地 |
| SCL | GPIO16 / P6-25 | 共享 I2C0 |
| SDA | GPIO17 / P6-30 | 共享 I2C0 |
| AD0 | GND | 7-bit 地址 0x68 |
| INT | 不接 | 首版 50Hz 轮询 |

GPIO16/17 同时挂载 GT911、SHT40 和 MPU6050。GT911 是唯一 I2C0 bus 创建者；MPU6050 只通过 `i2c_master_get_bus_handle()` 取得总线并添加自己的 device handle，禁止创建、删除或复位共享总线。

野火模块原理图显示 SDA/SCL 各有 2.2kΩ 上拉。接入 GT911、SHT40 后必须断电测量等效上拉，并确认所有上拉只到 3.3V；不得默认再焊额外上拉。

## 驱动参数

- I2C：100kHz，地址优先 0x68；初始化串行阶段也兼容探测 0x69。
- `WHO_AM_I`：寄存器 0x75，正确值固定为 0x68；即使设备地址是 0x69，该值仍是 0x68。
- 初始化：上电等待 100ms → 硬复位 → 等待 100ms → X 轴陀螺 PLL → 42Hz DLPF → 50Hz 输出。
- 加速度量程：±2g，16384 LSB/g。
- 陀螺仪量程：±250°/s，131 LSB/(°/s)。
- 温度：`raw / 340 + 36.53`。
- 采样：从 0x3B 一次 burst 读取 14 字节，保证加速度、温度和角速度来自同一采样时刻。
- 姿态变化：以驱动首次有效样本作为安装基线，不再把相对水平面的绝对倾角误当作门体变化量。
- 震动：`abs(|a| - 1g)`，静止时应接近 0。

驱动连续三次通信失败后将 IMU 标记为未就绪，并降为每秒一次的恢复探测。恢复只使用已注册的设备句柄，不会私自 reset/delete/recreate I2C0。

## USB / WebUI

WebUI 继续每约 300ms 发送：

```json
{"type":"request","request_id":"imu-1","command":"get_sensors"}
```

P4 minimal 固件会返回 `profile=p4_mpu6050`、总线/引脚、`imuReady`、`WHO_AM_I`、错误名、连续失败次数、样本计数、六轴、温度、Pitch/Roll、姿态变化和震动值。未迁移的光敏/PIR/门状态字段不再返回伪造零值，WebUI 会显示 `--`。

## 实机验收

1. 断电核对 3.3V、GND、SCL16、SDA17、AD0=GND、INT 悬空，并测量 SDA/SCL 等效上拉。
2. 启动日志依次确认 GT911、SHT40、MPU6050；MPU 行应包含 `addr=0x68 WHO_AM_I=0x68 50Hz`。
3. 连续查询 `get_sensors`，确认 `sampleCount` 递增且 WebUI 六轴数据刷新。
4. 静置检查加速度模长约 1g、震动值接近 0；分别绕三轴转动检查符号和量程。
5. 同时连续触摸并运行 SHT40/MPU6050 至少 10 分钟，确认无 I2C timeout、GT911 假释放、watchdog 或栈异常。
6. 状态机接回前，必须按真实冰箱门安装方向重新标定零偏和阈值；本次迁移不启用旧 S3 状态机。
